# 기술 결정 기록

## ADR-001 Secure-by-Default를 신규 설치 기본 정책으로 채택

- 결정:
  - 신규 설치에서 공개 기본 key를 금지한다.
  - 신규 설치에서 admin bind는 loopback 우선, admin TLS는 활성화 우선으로 간다.
  - insecure 모드는 명시적 opt-in으로만 허용한다.
- 이유:
  - 현재 가장 위험한 경로가 기본값 그대로의 배포에서 발생한다.

## ADR-002 테스트 우선, 보안 수정 후행

- 결정:
  - 각 취약점 수정 전 먼저 정상 기능 기준선 테스트를 추가한다.
  - exploit 차단 테스트는 가능한 경우 red 상태로 먼저 추가한다.
- 이유:
  - 테스트 부재 상태에서 보안 수정은 기능 회귀와 운영 장애를 부를 확률이 높다.

## ADR-003 테스트 가능한 seam 리팩토링은 보안 수정 전에 허용

- 결정:
  - `Environment`, 시간, 난수, TLS 옵션, 파일 쓰기, listener apply를 감싸는 seam 추가는 선행 허용한다.
  - 이 단계는 behavior-preserving refactor로 제한한다.
- 이유:
  - 현재 구조에서는 temp root, deterministic token, failure injection 없이 안정적인 테스트가 어렵다.

## ADR-004 Protocol v2는 점진적 도입

- 결정:
  - control/data trust 모델 강화는 capability negotiation과 dual-stack 기간을 거친다.
  - 운영 모드는 `legacy`, `mixed`, `mtls-strict` 3단계로 정의한다.
  - `allowedClientNames` 대체, authenticated identity, data channel binding, ID 폭 확장은 v2 묶음으로 본다.
- 이유:
  - 한 번에 protocol break를 내면 기존 client/server 호환성이 무너진다.

## ADR-004-1 자동 다운그레이드는 금지

- 결정:
  - TLS 검증 실패나 v2 협상 실패 시 자동 다운그레이드는 금지한다.
  - fallback은 명시적 설정과 경고 로그가 있을 때만 허용한다.
- 이유:
  - 조용한 다운그레이드는 보안 개선을 무력화한다.

## ADR-005 설정/인증서 변경은 stage/validate/commit 모델로 통일

- 결정:
  - 파일 쓰기와 런타임 적용을 분리한다.
  - commit 전에는 기존 리스너를 내리지 않는다.
  - rollback은 “이전 파일 복사”가 아니라 “last-known-good revision 재적용”으로 정의한다.
- 이유:
  - 현재는 저장 후 재시작 실패 시 서비스가 깨진 상태로 남는다.

## ADR-006 자원 방어는 session-local containment 우선

- 결정:
  - 큐, FileCache, handshake timeout 초과 시 프로세스 전체가 아니라 session 또는 connection 단위로 먼저 끊는다.
  - 전역 quota는 최후 안전장치로 둔다.
- 이유:
  - 공격 또는 느린 수신자 하나 때문에 전체 서비스가 흔들리면 운영성이 급격히 나빠진다.

## ADR-007 `5.6`은 정책/호환성 항목으로 분리

- 결정:
  - `replaceAccessControlAllowOrigin` 기본값 정리는 security hotfix 트랙이 아니라 정책/호환성 트랙으로 Phase 6에 둔다.
  - 다만 credential-bearing backend는 운영 점검 항목으로 조기 검토한다.
- 이유:
  - 브라우저 정책 성격이 강하고 실제 위험도는 backend auth model에 더 크게 의존한다.

## ADR-008 테스트 프레임워크는 Jest 유지, 하네스는 계층형으로 추가

- 결정:
  - 기존 Jest 설정을 재사용한다.
  - `test/helpers`, `test/fixtures`, `test/e2e`, `test/security`, `test/stress` 구조를 추가한다.
- 이유:
  - 저장소에 이미 Jest가 있고, 빠른 도입이 가능하다.

## ADR-009 일부 동작은 intentionally broken behavior로 전환

- 대상:
  - path traversal 허용
  - remote first-login bootstrap
  - 공개 기본 key
  - 인증서 미검증 TLS
- 결정:
  - 이 항목들은 “기존 기능 보존” 대상이 아니라 “깨져야 하는 취약 동작”으로 분류한다.
  - 대신 주변 정상 흐름은 기준선 테스트로 보존한다.

## ADR-010 문서와 샘플 설정은 마지막 Phase에서 동기화

- 결정:
  - README, sample config, version source는 최종 Phase에서 코드와 일치하도록 정리한다.
- 이유:
  - 중간 Phase에서 문서를 먼저 바꾸면 실제 동작과 다시 어긋날 수 있다.
