## Reuse and exact production design

Production write set is only `src/server/ServerOptionStore.ts` and `admin/src/layout/TunnelOptionSetLayout.svelte`.

In ServerOptionStore, reuse the existing result-returning validation pattern. Introduce one private server-buffer normalization/admission method taking the tunnel option and returning success/message (or the existing compatible result shape). It requires typeof value === 'number', Number.isFinite(value), value >= 1 and Number.isFinite(value * 1024 * 1024), assigns8 only for undefined, and does not touch client fields. No integer or safe-integer restriction applies. Use the same method from verificationTunnelingOption and verificationServerOption's supplied tunnel-list path: the latter currently does not validate nested tunnel buffer values, so POST/PUT /api/serverOption and commitPreparedServerOption must not bypass admission. Do not call the whole tunnel normalizer from generic server validation merely to validate this field: that could alter legacy CORS and other unrelated defaults. Preserve existing valid-list behavior and current result envelopes. Any discovered malformed-list behavior beyond this buffer requirement is reported separately rather than expanding schema validation.

composeServerOptionWithTunnelingOption already clones its argument before normalization. prepareServerOptionCommit also clones before preparation; tests must establish invalid candidates cannot publish or write. The existing YAML load path validates its local candidate before assigning _serverOption; a buffer validation failure must therefore retain non-ready status and original YAML/revision bytes. ServerApp.readServerOption already refuses before certificate load/CLI persistence/listeners: no ServerApp edit is needed. Keep explicit reset behavior unchanged.

Ordinary POST/PUT /api/tunnelingOption and applyCompoundTunnelingOption reuse compose/admission before port checks, persistence and runtime application. No AdminServer duplicate guard is planned. Failed input retains the existing HTTP400 failure envelope; do not replace it with a thrown exception or add a rollback write for validation-only failure. Correct-revision requests are used so stale-revision rejection cannot mask the buffer contract.

In the Svelte editor, remove only the server field's call to shared _normalizeMemBufferSize; retain that helper and invocation for the client. This avoids silently changing invalid server values or truncating legitimate fractions/large values. Add a local server validity predicate used with existing ServerOptionCtrl.checkValidTunnelingOption when computing updatable; ensure load/add/reactive paths cannot leave an invalid server row enabled. Preserve invalid typed values, disable Apply/Start and show a server-specific validation message. Add min=1 and step=any on the server input, without relying on native form validation alone because Apply is a click handler. Keep new-row10MiB as the existing explicit UI choice; backend omission remains8. Split shared help into explicit server finite minimum1MiB/fractions wording and unchanged client unlimited/spill policy. Do not change controller transport or global SocketHandler semantics.
