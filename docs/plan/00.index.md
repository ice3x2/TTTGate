# TTTGate 백엔드 보안/안정성 개선 계획

## 개요

| 항목 | 값 |
|------|-----|
| 목적 | 백엔드 보안 취약점과 운영 안정성 문제를 개선하되 기존 터널 기능을 단계적으로 보존 |
| 기술 스택 | Node.js 18+, TypeScript 5.1+, Jest, raw `net`/`tls`/`http` |
| 입력 문서 | `docs/analysis/2026-04-19-backend-security-functional-analysis.md`, `docs/backpressure_analysis_report.md`, `README.md` |

## 목적과 비목표

- 목적:
  - 관리자 서버 원격 장악 경로 제거
  - 제어/데이터 채널의 신뢰 경계 복구
  - 메모리/디스크/FD 고갈 방어 추가
  - 설정/인증서 변경의 원자성 확보
  - 테스트 부재 상태에서 기준선 기능을 먼저 고정한 뒤 단계별로 개선
- 비목표:
  - 프론트엔드 UI 전면 개편
  - 한 번의 릴리스에서 모든 프로토콜 호환성 제거
  - `5.6 HTTP 터널 CORS 완화`를 보안 hotfix로 취급하는 것

## 핵심 원칙

1. 테스트 먼저, 보안 수정 나중.
2. 취약 동작 주변의 정상 기능을 먼저 특성 테스트로 고정한다.
3. exploit 차단 테스트는 가능한 한 구현 전에 red 상태로 추가한다.
4. 설정/인증서/프로토콜 변경은 단계적 마이그레이션으로 진행한다.
5. 신규 설치는 secure-by-default, 기존 설치는 명시적 legacy opt-in으로만 예외를 허용한다.
6. `5.6`은 보안 hotfix가 아니라 정책/호환성 정리 항목으로 분리한다.
7. `baseline`과 `hardened` 증적은 같은 메트릭과 같은 evidence 경로로 비교한다.
