# 아키텍처 설계

## 목표

이 계획의 아키텍처 목표는 기존 코드베이스를 전면 재작성하지 않고, 테스트 가능한 seam과 적용/롤백 경계를 먼저 세운 뒤 보안과 안정성 수정을 단계적으로 넣는 것이다.

## 시스템 컨텍스트

### 주요 행위자

- 운영자: CLI와 관리자 UI를 통해 서버를 제어한다.
- 관리자 브라우저: admin API와 정적 자산을 사용한다.
- 터널 서버: control plane과 external listener를 관리한다.
- 터널 클라이언트: control plane에 등록하고 endpoint 연결을 관리한다.
- 외부 사용자: external port에 접속한다.
- 내부 endpoint 서비스: 터널 뒤에서 실제 트래픽을 처리한다.
- 공격자: admin HTTP, control/data handshake, 대기 큐, FileCache, 설정 변경 경로를 노린다.

## 타깃 경계

### 1. Admin Plane

- 포함:
  - `AdminServer`
  - `SessionStore`
  - 정적 자산 서빙
  - 관리자 설정/인증서 API
- 주요 변경:
  - path resolution guard
  - bootstrap token/local-only initialization
  - secure bind/TLS
  - secret handling

### 2. Control Plane

- 포함:
  - `TunnelServer`
  - `TunnelClient`
  - `CtrlPacket`
  - client identity
- 주요 변경:
  - TLS 검증
  - shared-key 제거
  - protocol v2 capability negotiation
  - authenticated client identity

### 3. Data Plane

- 포함:
  - `ClientHandlerPool`
  - `ExternalPortServerPool`
  - `EndPointClientPool`
  - `DataStatePacket`
  - `SocketHandler`
- 주요 변경:
  - queue limit
  - pause/resume
  - data channel binding
  - close/drain state machine

### 4. Runtime/State Plane

- 포함:
  - `ServerOptionStore`
  - `CertificationStore`
  - 환경 경로/버전
  - revision snapshot
- 주요 변경:
  - stage/validate/commit
  - last-known-good rollback
  - consistent response envelope
  - config/cert migration

### 5. Test Plane

- 포함:
  - `test/helpers/*`
  - `test/fixtures/*`
  - temp root/env overrides
  - process/in-process harness
- 주요 변경:
  - 기준선 특성 테스트
  - exploit regression test
  - long-running/pressure harness

## 설계 원칙

1. 수정 전 정상 기능을 먼저 테스트로 고정한다.
2. 보안 수정은 feature change가 아니라 contract tightening으로 본다.
3. 테스트성을 위해 필요한 리팩토링은 “행동 보존”만 수행한다.
4. 네트워크 경계는 versioned protocol과 explicit policy로만 바꾼다.
5. 설정/인증서 변경은 파일 쓰기와 리스너 적용을 분리한다.

## 핵심 컴포넌트 제안

| 컴포넌트 | 역할 | 기존 코드 |
|---------|------|----------|
| `EnvironmentProvider` | temp root, config path, cert path override seam | `Environment.ts` |
| `ClockRng` | 시간/토큰/nonce 결정성 확보 | `SessionStore`, `CertificationStore`, packet handshake |
| `TlsOptionsFactory` | client/server TLS 옵션 일관화 | `SocketHandler`, `TCPServer` |
| `ListenerApplyCoordinator` | stage/validate/apply/rollback orchestration | `ServerApp`, `TTTServer`, `AdminServer` |
| `QueueLimiter` | per-session/per-pool/global 바이트 상한 | `ClientHandlerPool`, `TunnelClient`, `SocketHandler` |
| `LifecycleStateMachine` | `open -> draining -> closed/aborted` 정합성 | `SocketHandler`, pool classes |
| `IdentityRegistry` | client id, fingerprint, token 관리 | `TunnelServer`, `CtrlPacket` |
| `TestHarness` | server/client/endpoint boot, temp dirs, event waiter | 신규 |

## 시퀀스 설계

### 시퀀스 A: 안전한 관리자 초기화

1. 서버 시작
2. bootstrap state 확인
3. remote login은 거부
4. local CLI 또는 one-time token으로 초기 관리자 설정
5. CSPRNG session token 발급
6. secure cookie와 bind policy 확인

### 시퀀스 B: 설정 변경 원자 적용

1. 새 설정 수신
2. schema/port/conflict/tls/cert preflight
3. staged file write
4. candidate listener 기동 또는 validation
5. 성공 시 revision commit
6. 실패 시 기존 revision 유지

### 시퀀스 C: protocol v2 연결

1. client connects with validated TLS
2. version/capability negotiation
3. challenge/response 또는 mTLS identity 확인
4. data handler one-time token 발급
5. data channel attaches using token
6. session opens only after binding success

### 시퀀스 D: 느린 수신자 처리

1. ingress buffer 증가
2. session limiter 초과 여부 확인
3. watermark 이상이면 `pause`
4. spill-to-file 조건 충족 시 bounded FileCache 사용
5. over-quota면 session fail-closed
6. queue/drain 완료 후 `resume`

## 테스트 하네스 아키텍처

### 계층 1. 순수 단위/계약 테스트

- packet parser/serializer
- option normalization
- path resolution
- session token generation contract
- queue accounting
- lifecycle state transition

### 계층 2. 컴포넌트 테스트

- `AdminServer` with temp `web/`, `config/`, `cert/`
- `ServerOptionStore` + staged file write
- `TunnelServer` + fake or loopback client
- `FileCache` quota/error behavior

### 계층 3. E2E 기준선 테스트

- server + client + echo endpoint
- admin login and static asset serving
- reconnect and session close
- config update and rollback

### 계층 4. 보안/부하 테스트

- path traversal reject
- unauthorized bootstrap reject
- MITM/trust failure reject
- slowloris timeout
- queue overflow containment
- long-running reconnect/timer leak

## 비보안 정책 항목

`5.6 HTTP 터널 CORS 완화`는 이 계획에서 security hotfix로 분류하지 않는다. 대신 Phase 6의 정책/호환성 정리 항목으로 다루며, 신규 설정 기본값과 마이그레이션 경고 정책만 정의한다.
