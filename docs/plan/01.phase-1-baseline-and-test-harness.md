# Phase 1: 기준선 테스트와 테스트성 확보

## 목표

보안 및 안정성 수정을 시작하기 전에 현재 서비스의 정당한 핵심 동작을 테스트로 고정하고, 이후 수정이 가능한 최소한의 테스트 seam을 추가한다. 이 Phase는 취약점을 고치는 단계가 아니라 “무엇을 지켜야 하고 무엇을 깨야 하는지”를 명확히 만드는 단계다.

이 Phase는 **리팩토링-only** Phase다. behavior-preserving seam 추가 외에는 보안 로직을 바꾸지 않는다.

## 상세 구현 지침

### 기준선 테스트 원칙

- 보존해야 하는 것:
  - 정상 static asset 제공
  - 정상 login/session 흐름
  - server-client control 연결
  - external TCP tunnel echo
  - reconnect와 정상 session close
  - config load/save roundtrip
- 깨져야 하는 것:
  - path traversal 허용
  - 원격 first-login bootstrap
  - 인증서 미검증 TLS
  - 공개 기본 key 기반 등록

### seam 추가 원칙

- seam은 동작 변경이 아니라 관측/주입/실패 주입만 가능해야 한다.
- 우선순위 seam:
  - path root override
  - clock/rng injection
  - TLS option builder
  - file write staging helper
  - listener boot helper
  - fakeable transport boundary
  - queue/cache budget policy boundary

## 테스트

### Given-When-Then 시나리오

1. 정상 케이스
   - Given temp `web/`에 `index.html`이 있다
   - When 관리자 서버에서 `/`를 요청한다
   - Then `200`과 `index.html` 본문이 반환된다
2. 정상 케이스
   - Given temp endpoint echo server, tunnel server, tunnel client가 실행 중이다
   - When external port로 문자열을 보낸다
   - Then 같은 문자열이 응답으로 돌아온다
3. 예외 케이스
   - Given 존재하지 않는 정적 파일 경로를 요청한다
   - When 관리자 서버가 요청을 처리한다
   - Then `404`를 반환한다
4. 예외 케이스
   - Given 잘못된 포트가 포함된 client option을 로드한다
   - When client app이 옵션을 해석한다
   - Then 예외 또는 명시적 오류를 반환한다
5. 경계값 케이스
   - Given 많은 reconnect를 반복하는 테스트 하네스가 있다
   - When client reconnect를 여러 차례 수행한다
   - Then 핵심 기능은 유지되고 타이머/세션 수는 안정 범위 안에 남는다

### 테스트 코드 템플릿

```ts
describe("baseline tunnel behavior", () => {
  it("should echo data through the tunnel without changing the current contract", async () => {
    const harness = await createBaselineHarness();
    await harness.start();

    const result = await harness.sendAndReceive("hello");

    expect(result).toBe("hello");
    await harness.stop();
  });
});
```
