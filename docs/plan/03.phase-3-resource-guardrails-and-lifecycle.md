## 상세 구현 지침

### 실패 정책

- quota 초과:
  - 프로세스 전체 종료 금지
  - 해당 세션 또는 connection만 fail-closed
- decompress upper bound 초과:
  - 메모리 전체 버퍼링 금지
  - rewrite bypass 또는 명시적 실패
- cache I/O 실패:
  - 세션 격리
  - 구조화된 운영 로그
  - cache file 정리
- handshake timeout:
  - 미인증 connection 즉시 종료

### 호환성 규칙

- 기존 설정 키는 유지한다.
- `-1`은 “unsafe override”로만 남기고 신규 설치 기본값은 유한값으로 바꾼다.

## 테스트

### Given-When-Then 시나리오

1. 정상 케이스
   - Given 느린 endpoint와 빠른 ingress가 있다
   - When 하이워터마크를 초과한다
   - Then 입력은 일시 정지되고 프로세스 메모리는 설정 상한 근처에서 plateau를 형성한다
2. 정상 케이스
   - Given 정상 세션이 drain 상태에 들어간다
   - When 모든 in-flight write가 끝난다
   - Then 세션은 한 번만 `Closed`로 전이된다
3. 예외 케이스
   - Given partial handshake packet만 보내는 연결이 있다
   - When deadline이 지난다
   - Then 연결은 종료되고 미인증 소켓 수가 감소한다
4. 예외 케이스
   - Given FileCache quota를 초과하는 느린 수신자가 있다
   - When spill quota를 넘긴다
   - Then 해당 세션만 종료되고 프로세스는 살아 있다
5. 경계값 케이스
   - Given reconnect를 수십 차례 반복한다
   - When `EndPointClientPool`이 매번 생성/정리된다
   - Then timer, fd, cache file count는 초기 안정 범위로 회복된다
6. 예외 케이스
   - Given 압축된 HTTP 응답이 비압축 시 상한을 넘는다
   - When body rewrite를 시도한다
   - Then rewrite는 우회되거나 명시적으로 실패하고 프로세스 RSS는 상한 안에 남는다

### 테스트 코드 템플릿

```ts
it("should contain a slow receiver within the configured memory and cache budget", async () => {
  const harness = await createPressureHarness({ queueLimitMb: 8, cacheLimitMb: 32 });
  const result = await harness.runSlowReceiverScenario();

  expect(result.processAlive).toBe(true);
  expect(result.offendingSessionClosed).toBe(true);
  expect(result.maxObservedRssMb).toBeLessThanOrEqual(128);
});
```
