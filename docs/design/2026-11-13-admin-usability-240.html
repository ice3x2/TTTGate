RESEARCH공통 근거

다섯 항목에 두루 쓰는 판단 기준입니다. 출처는 문서 끝에 모았습니다.

누르는 영역은 44px

WCAG 2.2의 2.5.8(최소 목표 크기, AA)은 24×24 CSS px를 요구하고, 2.5.5(AAA)는 44×44를 요구합니다. Apple HIG는 44×44pt, Material은 48×48dp를 권합니다. TTTGate는 이미 목록 스위치와 IP 갱신 버튼을 44px로 맞췄으므로(TunnelsScreen.svelte의 .tunnel-switch, .tunnel-ip-refresh) 새 조작도 44px을 기준으로 삼습니다. 모양이 작아야 하면 투명한 확장 영역(::before)으로 누르는 영역만 넓힙니다.

끌기에는 대안이 있어야 한다

WCAG 2.2의 2.5.7(끌기 동작, AA)은 끌어서 하는 조작에 한 번 누르기 대안을 요구합니다. Apple HIG도 정확한 값이 중요하면 슬라이더 옆에 스테퍼나 입력 칸을 두라고 권합니다. 24시간(1,440분)을 폭 약 260px 막대에 펴면 1px이 5분이 넘으므로, 끌기만으로는 "1분 단위"를 맞출 수 없습니다.

슬라이더 접근성

WAI-ARIA APG의 슬라이더 패턴은 화살표 한 칸, PageUp·PageDown 큰 칸, Home·End 양 끝을 정하고, 값이 숫자만으로 뜻을 갖지 않으면 aria-valuetext로 "1시간 30분"처럼 읽히게 하라고 합니다. 브라우저 기본 input type="range"가 대부분을 거저 주지만, PageUp·PageDown 폭은 브라우저마다 달라서 직접 정해야 합니다.

대비

WCAG 1.4.11(비텍스트 대비)은 버튼 경계처럼 조작을 알아보는 데 필요한 모양에 3:1, 1.4.3은 본문 글자에 4.5:1을 요구합니다. --line-2(#8A94A3)는 흰 바탕에서 약 3.0:1로 기준을 겨우 넘습니다. 관리 화면에는 어두운 테마가 없습니다(app.css에 prefers-color-scheme 규칙이 없음). 그래서 목업은 밝은 테마만 그렸습니다.

확인 창은 아껴 쓴다

NN/g는 확인 창을 자주 띄우면 사용자가 읽지 않고 누르는 습관이 생긴다고 경고합니다. 되돌리기 어렵고 결과가 큰 동작에만 묻고, 버튼은 "확인"이 아니라 동작 이름("차단")으로 적으라고 합니다. Apple HIG의 경고창도 파괴적 동작 버튼을 따로 표시하고 취소를 함께 둡니다. 그래서 다시 연결할 수 있는 "끊기"는 묻지 않고, 계속 남는 설정인 "차단"만 묻습니다.

점진적 공개와 Fitts 법칙

자주 쓰는 정보는 첫 화면에, 드물게 쓰는 조작은 한 번 더 눌러서 보이게 합니다(NN/g 점진적 공개). 목록 줄에는 숫자만 두고, 연결 목록과 차단은 창으로 미룹니다. Fitts 법칙에 따라 자주 누르는 대상은 크고 가깝게 둡니다. 연결 수 버튼을 줄 왼쪽 시작점, 엄지가 닿는 높이에 둔 이유입니다.

오류는 칸 옆에서, 미리

WCAG 3.3.1(오류 식별)과 3.3.3(오류 수정 제안), NN/g 오류 메시지 지침은 오류를 문제가 난 칸 가까이에, 무엇이 왜 틀렸고 어떻게 고치는지 적으라고 합니다. 오류보다 나은 것은 예방이므로, 상한을 입력 전부터 보입니다.

구조와 360px

WCAG 1.3.1(정보와 관계)과 2.4.6(제목과 이름)은 묶음을 제목으로 드러내라고 합니다. Apple HIG의 묶음 목록, Material 목록의 소제목과 같은 형태입니다. 폭 360px은 안드로이드 휴대폰에서 가장 흔한 CSS 폭 가운데 하나라서 모든 목업의 최소 폭으로 삼았습니다.

문제

  • 일·시간·분 숫자 칸 세 개(Timer.svelte:63-70)는 휴대폰에서 칸마다 키보드를 열고 닫아야 하고, "2시간 반"을 머릿속에서 칸별로 나눠야 합니다.
  • 창을 열면 남은 시간이 아니라 처음에 건 전체 시간이 보입니다(Timer.svelte:27-32). 남은 1시간을 늘리려고 연 창에 "8시간"이 보이면 사용자는 무엇을 바꾸는 것인지 헷갈립니다.
  • 그룹 상한보다 긴 값을 넣어도 서버가 말없이 자릅니다(ExternalPortServerPool.ts:763-765). 고른 값과 실제 값이 다릅니다.
  • 제목 "터널 사용 시간 제한"은 벌칙처럼 들리고, 사용자가 실제로 하는 일("얼마나 켜 둘지 정하기")과 거리가 있습니다.

사용 상황

휴대폰 · 엄지 하나

회의에 들어가기 직전, 집 NAS 터널이 20분 뒤 꺼지는 것을 보고 1시간 더 켜 두려 합니다. 창을 열면 지금 남은 20분이 이미 골라져 있고, 막대를 오른쪽으로 밀어 대략 맞춘 뒤 ＋를 두세 번 눌러 "1시간 20분"을 맞춥니다.

데스크톱 · 키보드

오후 내내 원격 작업을 하려고 8시간을 고릅니다. 슬라이더에 초점을 두고 PageUp을 여섯 번 누르면 1시간씩 늘어납니다. 화면 읽기 프로그램은 "켜 둘 시간, 8시간"이라고 읽습니다.

며칠 켜 두기

상한이 없는 관리자가 출장 사흘 동안 사무실 터널을 켜 둡니다. "일"을 누르고 3일을 고르면 "11월 16일 오후 3:10에 꺼집니다."가 보입니다.

상한이 짧은 그룹

상한이 12시간인 그룹의 사용자에게는 "일" 버튼이 없습니다. 막대 끝이 12시간이고, 아래에 "이 터널은 최대 12시간까지 켜 둘 수 있습니다."가 보입니다. 서버가 자를 값은 처음부터 고를 수 없습니다.

원칙

  1. 조작 하나, 결과 바로 보기. 막대를 움직이는 순간 값과 꺼지는 시각이 함께 바뀝니다. 사용자는 계산하지 않습니다.
  2. 서버가 받아들일 값만 고를 수 있다. 막대의 끝이 곧 실제 상한입니다(스펙 FR-1의 timeoutCapSeconds).
  3. 대략은 끌기로, 정확히는 누르기로. 끌기와 −/+ 버튼, 키보드가 같은 값을 움직입니다.
  4. 지금에서 출발한다. 창은 지금 남은 시간으로 열립니다. 확인은 "지금부터 다시 센다"는 뜻입니다.

창을 연 동안 남은 시간이 흐름처음 값은 연 순간의 남은 시간이다. 창을 연 채로 두어도 고른 값은 그대로이고, "꺼지는 시각"만 지금 기준으로 다시 계산한다(1초마다).
남은 시간 1분 미만1분으로 연다(스펙 FR-12).
남은 시간이 하루 이상이고 일 단위를 쓸 수 있음일 단위로 열고 일 수는 반올림한다. 예: 2일 5시간 → 2일.
자동으로 끄지 않는 터널(상한 없음)"자동으로 끄지 않기"가 켜진 채로 열린다. 막대와 단위 버튼은 흐리게 잠기고 값 자리에 "자동으로 끄지 않음"이 보인다.
켜기만 할 수 있는 사용자지금처럼 상태 영역에 시간 변경 창이 없다(스펙 1 결정 7, TunnelStatusArea.svelte:66의 editable). 목록의 시계는 보기만 한다.
꺼진 터널시간 변경 창을 열 수 없다(지금과 같음).
창을 연 동안 관리자가 그룹 상한을 줄임서버가 상한으로 자르는 기존 동작이 최종 판정이다. 창은 다음에 열 때 새 상한을 쓴다.
옛 서버(timeoutCapSeconds 없음)내 그룹 상한(/api/me)으로 계산한다(스펙 1 §7).

ITEM 2 · 스펙 2② 포트 범위 버튼 — 버튼답게

문제

  • 공용 버튼의 기본 모양 ghost는 테두리가 투명이고(Button.svelte:63), size="sm"은 12px 글자에 위아래 여백 5px입니다. 그래서 "범위 추가"와 "삭제"는 높이 약 28px의 회색 글자로 보입니다.
  • 범위가 없을 때는 "허용된 포트가 없습니다." 문장 아래에 이 글자 버튼만 남아 문장의 일부처럼 읽힙니다.
  • 범위 줄의 포트 입력 두 칸에는 보이는 이름도 보조 기술용 이름도 없습니다(GroupEditScreen.svelte:233-236). 화면 읽기 프로그램은 "편집, 1"만 읽습니다.
  • 터널 편집의 "허용 범위: 20000–20100, 30000–30010"은 안내 글자라서 눌러서 고를 수 없습니다.

사용 상황

관리자 · 데스크톱

새 그룹에 "20000–20100" 범위를 주려고 "허용 포트 범위"를 찾습니다. 비어 있는 상자 안에 테두리 있는 "＋ 범위 추가" 버튼이 바로 보입니다. 누르면 줄이 생기고 첫 칸에 초점이 갑니다.

일반 사용자 · 휴대폰

새 터널을 만들면서 외부 포트를 정해야 합니다. 칸 아래의 "20000–20100" 칩을 누르면 내 터널이 아직 쓰지 않는 첫 포트(예: 20002)가 들어갑니다.

권장 설계

  • secondary 모양을 더합니다. 흰 바탕(--bg-2), 테두리 --line-2, 글자 --ink-0, 최소 높이 44px. 기존 .btn 기본 규칙과 같은 테두리를 쓰므로 새 색은 없습니다. 기본값 ghost는 그대로라 대화 상자의 "취소"는 바뀌지 않습니다.
  • "＋ 범위 추가"는 아이콘과 글자를 함께 둔 secondary입니다. 범위가 없으면 점선 상자 안에 문장과 나란히 둡니다.
  • 줄 삭제는 44px 정사각 아이콘 버튼(×)입니다. 보조 기술용 이름은 "20000–20100 범위 삭제"입니다. 360px에서 입력 두 칸에 폭을 더 줄 수 있고, 같은 줄에 "삭제" 글자가 반복되지 않습니다.
  • 삭제는 빨간색과 확인 창을 쓰지 않습니다. 저장 전에는 되돌릴 수 있는 편집이기 때문입니다. 빨간색은 저장된 것을 지우는 동작(터널 삭제 등)에만 씁니다.
  • 포트 입력 두 칸 사이에 "–"를 두고, 보조 기술용 이름 "시작 포트"·"끝 포트"를 붙입니다.
  • 터널 편집 화면에서는 허용 범위를 칩 버튼으로 보입니다. 누르면 그 범위에서 내 터널이 쓰지 않는 가장 작은 포트를 넣고, 모두 쓰고 있으면 첫 포트를 넣습니다. 칩 높이는 36px이고 누르는 영역은 44px까지 넓힙니다.

ITEM 3 · 스펙 3③ 연결당 버퍼 — 그룹 최대치

문제

  • 일반 사용자는 버퍼를 아주 크게 잡아 서버 메모리를 혼자 쓸 수 있습니다. 지금은 서버 버퍼만 전역 캐시 한도로 검사하고, 클라이언트 버퍼는 검사하지 않습니다(AttributeEnforcer.ts:169-174).
  • 상한을 넣더라도 사용자가 그 숫자를 모르면, 저장을 눌러야 비로소 실패를 알게 됩니다.

사용 상황

관리자

"외부 협력사" 그룹의 연결당 버퍼를 16 MiB로 묶습니다. 그룹 편집의 "제한" 카드, 최대 동시 연결 바로 아래에서 숫자를 넣습니다.

일반 사용자

새 터널을 만들면 버퍼 기본값이 이미 10(상한이 8이면 8)으로 들어가 있습니다. 큰 파일을 보내려고 128을 넣는 순간 칸 아래에 "그룹 최대 16 MiB 이하로 정하세요."가 보이고 저장 버튼이 잠깁니다.

상한을 낮춘 뒤

예전에 64로 저장해 둔 터널을 열면 버퍼 카드에 주황색 안내가 보입니다. 이름만 고쳐 저장하는 것은 됩니다. 버퍼를 바꾸려면 16 이하로 정해야 합니다.

옛 화면 · API 직접 호출

화면 검사를 거치지 않은 요청은 서버가 422로 거부하고, 알림에 "서버 버퍼는 그룹 최대인 16 MiB 이하여야 합니다."가 보입니다.

권장: 카드 이름을 "세션당 버퍼 한도(MiB)"에서 "연결당 버퍼 한도(MiB)"로 바꿉니다. 관리 화면에는 이미 "세션" 화면이 있고, 거기서 세션은 관리자 로그인 세션입니다(sessions.*: "세션 끝내기", "활성 세션이 없습니다"). 이 버퍼는 터널로 들어온 TCP 연결 하나에 걸리며, ④에서 그 단위를 화면 문구로 "연결"이라 부르기로 했습니다(스펙 4 결정 1). 같은 대상을 화면마다 다른 이름으로 부르면 사용자는 다른 것으로 읽습니다. 책임자 표현의 "세션당 버퍼 한도"는 지금 카드 이름을 가리킨 것이므로 뜻은 그대로입니다.

검토한 대안

대안쓰지 않은 이유
넘으면 서버가 상한으로 잘라서 저장사용자가 모르는 사이에 값이 바뀐다. ①에서 고치려는 "말없이 자르기"와 같은 문제다. 책임자 지시도 "저장되지 않는다"이다.
화면이 입력값을 상한으로 자동 고정입력한 숫자가 몰래 바뀌어 사용자가 무엇이 틀렸는지 배우지 못한다. 오류를 보여 주고 고치게 한다.
서버·클라이언트 상한을 따로스펙 3 결정 2에 동의한다. 카드 하나에 숫자 하나가 관리자에게 쉽다.
슬라이더MiB는 정확한 숫자를 넣는 값이고 범위가 넓다. 숫자 칸이 맞다.
저장을 잠그지 않고 누르면 오류로 이동지금 버퍼 화면은 오류가 있으면 저장을 잠근다(updatable). 같은 화면 안에서 규칙을 둘로 나누지 않는다. 오류 문구가 늘 보이므로 왜 잠겼는지 알 수 있다.

문제

  • 목록 줄은 "켜짐 · 연결 2개"까지만 보입니다. 주고받은 양과 연결된 주소를 보려면 편집 화면으로 들어가야 하고, 거기서도 주소 목록은 볼 수 없습니다.
  • 수상한 연결을 끊는 방법은 터널 전체를 끄는 것뿐입니다. 차단은 보안 화면에서 주소를 직접 타이핑해야 합니다.
  • 어느 클라이언트가 이 터널을 이어 주는지 목록에서 보이지 않습니다. "클라이언트 연결 끊김"이 떠도 어느 PC를 켜야 하는지 모릅니다.

사용 상황

소유자 · 휴대폰

알림을 받고 목록을 엽니다. ssh-office 줄의 "연결 3"을 누르면 주소 세 개가 보입니다. 모르는 주소 하나를 "끊기"로 바로 끊습니다. 소유자에게는 차단 버튼이 없으므로 관리자에게 주소를 전달합니다.

슈퍼유저 · 데스크톱

같은 주소에서 연결이 계속 들어옵니다. "차단"을 누르면 확인 창이 뜹니다. "이 터널만"이 기본으로 골라져 있고, 차단하면 그 주소의 연결 두 개가 함께 끊깁니다.

켜기만 하는 사용자

"연결 3"은 버튼이 아닌 글자입니다. 주소(개인정보)는 보이지 않고, 가동 정보와 허용 클라이언트는 보입니다.

클라이언트가 꺼짐

"클라이언트: ○ 사무실 PC"가 흐리게 보이고 상태 줄에는 "클라이언트 연결 끊김"이 보입니다. 사무실 PC를 켜야 한다는 것을 바로 압니다.

"가동 시간"의 뜻 — 스펙 결정 3을 바꾸기를 권합니다

목록에서 "가동 시간"은 "이 터널을 켠 지 얼마"로 읽힙니다. 그런데 지금 uptime은 서버가 그 포트를 연 시각입니다(ExternalPortServerPool.ts:208). 터널을 꺼도 포트는 열려 있으므로(inactive는 상태만 바꿈), 방금 켠 터널의 줄에 "가동 시간 3일"이 보입니다. 스펙 결정 3이 짚은 대로 activeStart는 켜 둘 시간을 바꿀 때마다 다시 잡혀 쓸 수 없습니다.

권장: 상태 응답에 activatedAt(꺼짐→켜짐으로 바뀐 시각, 켜 둘 시간을 바꿔도 그대로)을 더하고, 목록과 편집 화면 모두 "켜진 지 {duration}"을 보입니다. 서버가 다시 시작해 상태를 이어받으면 이어받은 값을 씁니다. 옛 서버(필드 없음)면 지금처럼 "가동 시간 {uptime}"을 보입니다. 두 화면이 같은 함수로 이 줄을 만드는 스펙 FR-1의 원칙은 그대로입니다.

  • 차단 확인 창은 연결 창 위에 겹쳐 띄웁니다. 제목은 질문("… 주소를 차단할까요?"), 범위는 큰 라디오 두 개("이 터널만"이 기본), 메모는 선택, 버튼은 "취소"와 빨간 "차단"입니다.

  • 겹친 창의 Esc. 지금 Modal.svelte는 창마다 window의 keydown을 듣고 Esc면 닫습니다. 확인 창을 연결 창 위에 띄우면 Esc 한 번에 둘 다 닫힙니다. 맨 위 창만 Esc에 반응하고, 닫으면 초점이 그 창을 연 "차단" 버튼으로 돌아가야 합니다. 오버레이를 누를 때도 맨 위 창만 닫습니다.
  • 알약 버튼의 보조 기술용 이름은 "연결 3개 보기"입니다. 버튼 안의 "›"는 숨깁니다.
  • 연결 창의 "끊기"·"차단" 버튼 이름에 주소를 붙입니다: "203.0.113.7 연결 끊기". 같은 이름의 버튼이 줄마다 반복되면 화면 읽기 프로그램 사용자가 어느 줄인지 모릅니다.
  • 끊거나 차단한 결과는 알림(토스트)으로 알리고, 알림 영역은 role="status"입니다.
  • 2초 새로 고침은 화면 읽기 프로그램에 매번 알리지 않습니다. 새 연결이 붙을 때만 "새 연결 1개"를 조용히 알립니다.
