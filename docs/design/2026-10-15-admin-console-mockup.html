Blocked n 의 숫자는 보안 화면 Rejections 표의 같은 포트 행을 더한 값입니다. 20010 은 0 + 1532 + 41 = 1573, 20011 은 17 + 0 + 2 = 19 입니다. Blocked {n} 의 n 은 천 단위 구분 쉼표 없이 그대로 적습니다. 0 이면 칩을 그리지 않고, online 이 아닌 행(Error·Offline)에는 아예 그리지 않습니다. Add 버튼과 한도 안내는 #108 이 정한 배타 관계입니다. 버튼은 policy.canCreate(ownedCount) 일 때만 그립니다 — 제한 없는 슈퍼유저이거나, tunnel_crud 가 full 이고 max_tunnel_count 가 0 보다 크며 가진 수가 그 한도보다 적을 때입니다. 그 조건이 깨지면 버튼이 사라지고, 한도에 닿은 경우에만 목록 위에 <p id="tunnel-limit-note"> 로 Tunnel limit reached (n/max). 가 나옵니다. 둘은 동시에 성립하지 않습니다. 이 시안의 일반 유저는 Field team(max_tunnel_count: 10)이고 가진 터널이 둘이라 버튼만 보이고 안내는 없습니다. 상태는 세 갈래로만 갈립니다. status.online 이면 Online, 상태가 있는데 online 이 아니면 Error, 상태 자체가 없으면 Offline 입니다. 타임아웃이 0 이하면 ∞ 로 적습니다. 행마다 data-port 를 달았습니다 — 명세(docs/design/issues/unit1.md)의 수용 기준이 [data-port="20001"] 같은 선택자로 행을 찾고, [data-port="…"] [data-owner]·[data-readonly]·[data-blocked] 를 그 안에서 단언합니다. 명세의 목록은 <ul> 안의 <li data-port> 카드이고 이 목업은 표의 <tr data-port> 로 옮겨 적었습니다. 상세로 가는 길은 a.tunnel-link 하나이며 href 는 #/tunnels/{forwardPort} 입니다. 이동은 <a href> 의 기본 동작이고 onclick·navigate() 를 쓰지 않습니다. 활성 스위치와 타임아웃은 링크 밖입니다 — 명세가 소유자 칩과 read only 칩만 링크 안에 두고 Activation Switch 와 Timeout Timer 를 링크 밖에 두기 때문이며, 카드를 여는 클릭이 스위치에 떨어지지 않게 하려는 것입니다. 오프라인 행(30010)도 링크를 가집니다 — 상태와 무관하게 편집 화면으로 들어갈 수 있습니다. .tunnel-link 의 선언 셋(display:block·color:inherit·text-decoration:none)은 원본 TunnelsScreen.svelte:193 에서 그대로 가져왔습니다.

목업 전용 조치 네 링크에 붙은 data-s="tunneledit" 와, 목업 스크립트가 <a> 의 기본 동작을 preventDefault 로 막고 화면을 바꾸는 것은 원본에 없습니다. 이 목업은 열세 화면을 한 문서에 담아 해시 라우터가 없기 때문입니다. 실제 구현은 <a href> 의 기본 동작으로 이동하고 클릭을 가로채지 않습니다. 또 편집 화면이 문서에 하나뿐이라 네 행의 링크가 모두 같은 Tunnel 20010 화면을 엽니다 — 실제로는 포트마다 다른 터널이 열립니다.

Field team 은 HTTP_REWRITE 가 없고 네 플래그가 모두 false 이므로 이 카드 전체가 일반 유저에게 없습니다. 카드 안의 Replace host (address) in text body 도 Disabled 로 둡니다. 새 터널의 기본값만 rewriteHostInTextBody: true 입니다. 카드에 남은 헤더 주입 한 줄과 본문 치환 한 줄도 두 편집기의 생김새를 보이려고 값을 둔 것입니다. 소유자(@alice)는 이 값들 때문에 잠기지 않습니다.
