한 행에 키가 여럿이면(예: clock.* 셋) 한 건으로 셉니다. 열린 HIGH·MEDIUM 은 없습니다. 모든 항목의 최종 문구가 정해졌고, 아래 두 가지만 문구 밖의 코드 작업이 함께 필요합니다: nav.status 새 키, 관리 화면 포트·TLS 변경 뒤 화면 이동.

검토 과정

  1. 1차
    제안. ko.ts 키 776개를 en.ts·화면 코드·서버 코드와 대조했습니다. 뜻이 틀린 것, 번역투, 화면마다 다른 이름, 메뉴 이름, 긴 설명, 띄어쓰기, 영어로 남은 것의 일곱 갈래로 권장안을 냈습니다.
  2. 2차
    독립 검증. 1차 근거를 코드로 다시 확인했습니다. "적용하고 다시 시작은 실제로 다시 시작하지 않는다"는 1차 주장이 틀린 것을 찾아 버튼을 "저장하고 다시 시작"으로 고쳤습니다. "HTTP 다시 쓰기" 용어를 정하고, 1차가 놓친 17건(N1~N17)을 더했습니다.
  3. 3차
    사실 재확인과 통합. 2차안 12건을 고쳤습니다. 사실 오류 3건(startupHint, group.maxDurationHint, server.restarted 근거), 키 공유 누락 1건(nav.status), 겹침·번역투 정리, 심각도 조정 2건이 있습니다. 4건을 새로 찾고, 코드 문제 3건과 en.ts 동반 수정 5건을 정리했습니다.
  4. 4차
    3차 변경분만 독립 검증. 3차가 고치거나 더한 16건을 소스로 다시 확인했습니다. 13건은 확인했고 3건을 고쳤습니다: tunnelEdit.startupHint(포트를 열지 못한 터널의 예외를 다시 넣음), auditEvent.group_attributes_changed("권한·한도"가 좁아 "그룹 설정 변경"으로), clients.runOnHost("둘 컴퓨터"가 숫자 2로 읽힘). 코드 문제 3건은 모두 사실로 확인했습니다.

책임자가 정한 것(바꾸지 않음)

  • 속도 제한 → 연결 횟수 제한. 거절 사유는 "연결 횟수 초과", 칸 이름은 "IP당 최대 연결 횟수"입니다.
  • HTTP 다시 쓰기·HTTP 옵션 → HTTP 헤더·본문 바꾸기. API 필드 이름 HTTP_REWRITE 는 그대로 둡니다.
  • 2.4.0 용어: "켜 둘 시간", 남은 시간은 "자동 꺼짐까지", 터널 트래픽 단위는 "연결", 관리 화면 로그인만 "세션"입니다.

문구가 아닌 코드 문제(보고)

권장: 첫 줄(관리 화면 포트·TLS 변경 뒤 화면 이동)은 문구를 고쳐도 막지 못하므로 문구 작업과 같은 릴리스에서 고치기를 권합니다. 저장 확인 창에서 옛 주소에 머물고 "TTTGate 서버를 다시 시작한 뒤 새 주소로 접속하세요"라고 안내하는 쪽이 가장 단순합니다. 나머지 둘은 문구 작업과 함께 처리하면 됩니다.
